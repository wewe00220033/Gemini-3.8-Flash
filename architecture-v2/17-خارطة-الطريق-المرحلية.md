# 17 — خارطة الطريق المرحلية 360° (Prioritized Roadmap)

> **الهدف:** مراحل **قابلة للدمج والاستخدام كلٌّ على حدة**، مرتبة بالخطورة ثم بالقيمة، لكل مرحلة: النطاق، الملفات، الأسئلة التي يجب حسمها قبلها، تعريف الاكتمال (DoD)، وبوابة القبول.
> **المبدأ:** استقرار قبل ميزات. **لا تُبنى ميزة على بوت يموت.** كل مرحلة = فرع + PR مستقل = لا دمج بدون موافقة.

## 0. نظرة عامة

```
المرحلة 0  ─ أساس آمن (أدوات مشتركة + أمان P0)                 ≈ 1 PR    ┐
المرحلة 1  ─ استقرار الشبكة: heartbeat + مهلات + Session + FIFO    ≈ 2 PR    │ P0 — الحوادث
المرحلة 2  ─ Failover v2: قفل متدرج + قفزات + ميزانية + تأجيل      ≈ 1–2 PR  ┘
المرحلة 3  ─ خط الإنتاج: أرشفة + قاموس + أدوار + رسالتان           ≈ 3 PR    ┐
المرحلة 4  ─ الجلسات + التسمية + السياق 2-strike                   ≈ 2 PR    │ P1 — الرؤية
المرحلة 5  ─ السجلات + النسخ + /trace + تقرير الحادث + /doctor      ≈ 2 PR    ┘
المرحلة 6  ─ اللوحة + FSM + /set + setMyCommands                   ≈ 2 PR    ┐ P2 — الراحة
المرحلة 7  ─ /ask /chat /plan + web parity + stats/find            ≈ 2 PR    ┘
المرحلة 8  ─ المؤجلات (P3) — بعد شهر استخدام
```

**ترتيب القيمة/الخطورة:** 0→1→2 إلزامي بالترتيب. 3→5 يمكن تبديل 5 قبل 4 لو حدث حادث جديد. 6→7 حسب رغبة المالك.

## المرحلة 1 — استقرار الشبكة (الحوادث 02/03)
**الفروع:** `feat/v2-phase1a-heartbeat-timeouts` ثم `feat/v2-phase1b-fifo-queue`
**لماذا:** السبب المباشر للحوادث؛ أعلى قيمة بأقل كود.

### 1a — النبض والمهلات والجلسة (~150 سطر، `telegram_bot.py` + `main.py` + `config.py`)
- `requests.Session` لكل خيط + `HTTPAdapter(max_retries=0)` + إعادة إنشاء عند `ReadTimeout/ConnectionError`.
- مهلات tuples: `TG_CONNECT_TIMEOUT=10`, `TG_POLL_TIMEOUT=30`, read = poll+15.
- watchdog يقرأ `STATE["last_poll_ok"]` و`last_job_ok`؛ stall > `HEARTBEAT_STALL_SECONDS=90` → `stop_event` + خيط جديد؛ وضع حماية بعد 3 إعادات/10د.
- 409 يُبلَّغ مرة واحدة.
- `allowed_updates` يبقى `message` فقط هنا (callback في المرحلة 6).

### 1b — طابور FIFO + إيصال فوري + تحميل متين (~250 سطر، `voice_queue.py` جديد)
- `queue.Queue(maxsize=QUEUE_MAX=50)`؛ `TRANSCRIBE_WORKERS=1`؛ `SEND_WORKERS=1`.
- إيصال "⏳ تم الاستلام — رقمك N/M" فوراً (قبل التحميل)؛ يُعدَّل إلى "جارٍ التفريغ" ثم يُحذف.
- تحميل retry ×3 (2/5/10) بمهلة ديناميكية؛ رسائل مميزة `📡 تليجرام:` vs `🤖 Gemini:`.
- `jobs.ndjson` (received/downloaded/attempt/sent/failed) + `file_unique_id` idempotency 24س.
- `/queue` يعرض الطابور.

**يُحسم قبلها:** Q2 (عامل واحد)، Q6 (سياسة الخروج).
**DoD:** 03 §6 كامل (7 بنود) + تمرين حي 6 فويسات على الاستضافة **موثق بلقطة سجل**.
**بوابة القبول:** 48 ساعة على الاستضافة بلا stall > 90ث غير معالَج تلقائياً (من `events`).

## ملحق ب — بوابة كل PR ("درع ضد الوكيل" [ج3] مُكيَّف)
قبل طلب الدمج، يجيب الوكيل كتابةً في وصف الـ PR:
1. ما المشكلة الحقيقية التي يحلها هذا الـ PR (رابط للحادث/المتطلب)؟
2. كم سطراً صافياً أُضيف؟ هل أُضيف اعتماد؟ (حد 400 / لا).
3. هل لُمست النواة المحمية؟ أين الـ regression؟
4. ما الذي **اختُبر فعلاً** (أمر + نتيجة) وما الذي **لم يُختبر**؟
5. كيف نتراجع (rollback) لو فشل على الاستضافة؟ (العلم `FEATURE_*` = 0 يكفي؟)
6. أي سؤال من 16 اعتُمد فيه افتراضي دون جواب؟

**أعلام حمراء ترفض الـ PR تلقائياً:** تغيير قائمة الموديلات بلا أمر من المالك؛ إضافة Lite للتفريغ؛ حذف اختبار؛ طباعة سر؛ تعديل `.bat`؛ دمج ذاتي.
