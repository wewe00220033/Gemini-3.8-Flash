# 17 — خارطة الطريق المرحلية 360° (Prioritized Roadmap)

> **الهدف:** مراحل **قابلة للدمج والاستخدام كلٌّ على حدة**، مرتبة بالخطورة ثم بالقيمة، لكل مرحلة: النطاق، الملفات، الأسئلة التي يجب حسمها قبلها، تعريف الاكتمال (DoD)، وبوابة القبول.
> **المبدأ:** استقرار قبل ميزات. **لا تُبنى ميزة على بوت يموت.** كل مرحلة = فرع + PR مستقل = لا دمج بدون موافقة.

## المرحلة 1 — الاستقرار والتعافي الذاتي (الحوادث 02/03) — **مُعاد تصميمها في الجولة 2**
**الفروع:** `feat/v2-phase1a-self-healing` ثم `feat/v2-phase1b-priority-queue` ثم `feat/v2-phase1c-supervisor`
**لماذا:** السبب المباشر للحوادث؛ و**أعلى أولوية عند المالك** (Zero-Touch). التفصيل الكامل في **03b**.

### 1a — الطبقات 1–3: اكتشاف مبكر + قتل الـ socket + watchdog مستقل (~230 سطر)
- Session لكل خيط + `HTTPAdapter(max_retries=0, socket_options=keepalive)` + `session.close()` عند أي خطأ شبكي (03b الطبقة 2).
- مهلات tuples؛ `TG_POLL_TIMEOUT=30` → **10 في وضع الحذر** 5 دقائق بعد أي ReadTimeout (03b الطبقة 1)؛ backoff شبكي 3→30ث.
- **`time.monotonic()`** لكل النبضات (D22).
- نبضات: `last_poll_ok` (موجود) + `worker_beat` + `watchdog_beat` + `notifier_beat`.
- خيط watchdog **مستقل لا يلمس الشبكة** + طابور إشعارات؛ فحص كل 10ث؛ stall = poll+margin+15 (≈55ث لا 90).
- سلم L0→L3 + **L3b short-poll طوارئ** (19 §1)؛ 409 يُبلَّغ مرة واحدة؛ 401 يوقف الـ poller.
- `/health` عميق (503 عند stall).

### 1b — طابور أولوية + إيصال فوري + تحميل متين + مهلة مهمة (~300 سطر، `voice_queue.py`)
- `PriorityQueue((ready_at, seq))` بدل FIFO صرف — **يتخطى المؤجَّل** (19 §2، D21)؛ `TRANSCRIBE_WORKERS=1`, `SEND_WORKERS=1`, `QUEUE_MAX=50`.
- إيصال "⏳ تم الاستلام — رقمك N/M" فوراً؛ يُعدَّل ثم يُحذف (مع معالجة S5–S7 في 18).
- تحميل retry ×3 بمهلة ديناميكية؛ `📡 تليجرام:` vs `🤖 Gemini:`.
- `JOB_HARD_TIMEOUT=240` بـ future + إعادة worker (L2).
- `jobs.ndjson` + `file_unique_id` idempotency + الجلسة والإعدادات حسب D25/D26.
- قبول `video_note`/`video` ≤ 20MB (N3) + `MAX_AUDIO_MINUTES`.
- `/queue`.

### 1c — الطبقة 4: Supervisor/Worker في `main.py` (~110 سطر) — **اختيارية `SUPERVISED=0` [قرار-مالك ج3]**
- المشرف النحيف بلا imports من المشروع؛ ملف نبض؛ `terminate→kill`؛ backoff (5,10,20,60)؛ حد 20/ساعة؛ `--generation N`؛ `restart_reason.json`؛ `SUPERVISED=1` يفعّل L4.
- DEPLOY.md: Startup = `python main.py` (يعمل كمشرف) + قسم UptimeRobot على `/health` (الطبقة 5).

**يُحسم قبلها:** N3 (الفيديو)، N4 (مستوى الإشعارات). الباقي له افتراضي.
**DoD:** 03 §6 + **03b §7 (8 بنود، منها MTTD ≤ 60ث، تمرين قطع الشبكة، تمرين kill -9)**.
**بوابة القبول:** **أسبوعان** على الاستضافة بلا تدخل يدوي واحد (03b §7 بند 8)؛ مؤقتاً 48 ساعة لفتح المرحلة 2 بالتوازي.

## ملحق ب — بوابة كل PR ("درع ضد الوكيل" [ج3] مُكيَّف)
قبل طلب الدمج، يجيب الوكيل كتابةً في وصف الـ PR:
1. ما المشكلة الحقيقية التي يحلها هذا الـ PR (رابط للحادث/المتطلب)؟
2. كم سطراً صافياً أُضيف؟ هل أُضيف اعتماد؟ (حد 400 / لا).
3. هل لُمست النواة المحمية؟ أين الـ regression؟
4. ما الذي **اختُبر فعلاً** (أمر + نتيجة) وما الذي **لم يُختبر**؟
5. كيف نتراجع (rollback) لو فشل على الاستضافة؟ (العلم `FEATURE_*` = 0 يكفي؟)
6. أي سؤال من 16 اعتُمد فيه افتراضي دون جواب؟

**أعلام حمراء ترفض الـ PR تلقائياً:** تغيير قائمة الموديلات بلا أمر من المالك؛ إضافة Lite للتفريغ؛ حذف اختبار؛ طباعة سر؛ تعديل `.bat`؛ دمج ذاتي.
