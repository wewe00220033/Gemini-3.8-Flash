# 05 — القاموس المخصص (Glossary)

> **الهدف:** تحويل ألقاب المالك وكلماته المنطوقة إلى المصطلح الصحيح **بأمان**، دون "بحث واستبدال أعمى" يفسد الكلام العادي.
> **المصادر:** [م1] الألقاب الخام، [ج6] التصميم المعتمد، [ج3] "نوعان من القاموس"، [ج1] M04 `context_rules` + اقتراحات معتمدة، [شات].

## 1. ما قاله المالك حرفياً [م1 + شات] — المصدر الوحيد للألقاب

| اللفظ المسموع | المقصود | درجة التأكيد |
|---|---|---|
| شلباي / شلبي | ChatGPT | **مؤكد** |
| جرافيك / AntiGrafitti | Antigravity (IDE من جوجل) | **مؤكد** |
| فلاش | عائلة Gemini Flash (3.8/3.7/3.6…) | **مؤكد** — لكن **أي إصدار؟** غير محدد |
| سانتا | Sonnet (Claude) | **مؤكد** |
| أوبس / أوبوس | Opus — "تبع كلود كود موديل" | **مؤكد** |
| فافل / فابل | شيء "تبع كلود" — "ف أ ب ل" | **غير مؤكد المقصود** — المالك وصف الحروف فقط |
| أسترا | "تبع ChatGPT" | **غير مؤكد المقصود** |

### ⚠️ أخطاء في المسودات السابقة يجب عدم ترحيلها
- [ج6] ثبّت `أسترا → Astra` و`فابل → Fable` كقيم افتراضية في `glossary.json` — **افتراض غير مؤكد**.
- [ج1] D-قرارات ادّعى "فابل = Claude Fable عبر بحث ويب" — لا يوجد منتج بهذا الاسم معروف؛ **نرفض اعتماده**. قد يقصد المالك "Claude **Code**"؟ أو ميزة باسم آخر. → **سؤال Q4** للمالك.
- [ج6] وضع `فلاش → Gemini-Flash` عاماً — مقبول كبداية، لكن في سياق "3.6 فلاش" يجب أن يصبح `Gemini 3.6 Flash` (قاعدة سياق).

**القرار [رأينا]:** القيم الافتراضية الأولية تحتوي **المؤكد فقط** (5 مدخلات). غير المؤكد يُضاف **مُعلَّقاً** (`pending`) ويظهر للمالك ليؤكده من البوت.

## 2. نوعان من القاموس [ج3 — نقبله كاملاً، فهو يحل تعارضاً حقيقياً]

| النوع | مثال | أين يُطبَّق | لماذا |
|---|---|---|---|
| **إملائي/تصحيحي** (`spelling`) | "جرافيك" → "Antigravity"، "انتي جرافيتي" → "Antigravity" | **الخام والمنظم** | هذا تصحيح لما قيل فعلاً |
| **لقب/كناية** (`alias`) | "شلبي" → "ChatGPT"، "سانتا" → "Sonnet" | **المنظم فقط** — الخام يبقى "شلبي" | الخام = ما نُطق فعلاً (أمانة النص)، المنظم = المعنى |

- حقل `scope` لكل مدخل: `both` (افتراضي للإملائي) / `polished_only` (افتراضي للألقاب) / `raw_only`.
- المالك قال "تفريغ حرفي" للخام — لذا الألقاب لا تُغيَّر فيه إلا لو اختار المالك `both`.

## 3. مخطط المدخل (schema) — دمج ج6 + ج1 M04

```json
{
  "schema_version": 1,
  "entries": [
    {
      "id": "g_001",
      "patterns": ["شلبي", "شلباي", "شلبى"],
      "replacement": "ChatGPT",
      "kind": "alias",
      "scope": "polished_only",
      "status": "confirmed",
      "context_rules": [],
      "hits": 0,
      "created": "2026-10-25T00:00:00Z"
    },
    {
      "id": "g_004",
      "patterns": ["أوبس", "اوبس", "أوبوس"],
      "replacement": "Opus",
      "kind": "alias",
      "scope": "polished_only",
      "status": "confirmed",
      "context_rules": [{"if_near_any": ["ستوديو", "تسجيل الشاشة", "بث"], "then": "skip"}],
      "hits": 0
    }
  ]
}
```

### قواعد التطبيق
1. **حدود الكلمة** مع مراعاة السوابق العربية: `(?<![\w\u0600-\u06FF])(?:و|ف|ب|ل|ال|وال|بال|لل)?(شلبي|شلباي)(?![\w\u0600-\u06FF])` — السابقة تُحفظ ("وشلبي" → "وChatGPT").
2. **تطبيع الهمزات والياء** في المطابقة فقط (أ/إ/آ → ا، ى → ي، ة → ه) — لا في النص الناتج.
3. **`context_rules`** للتمييز [ج1 M04]: أوبس ↔ OBS Studio، فلاش ↔ فلاشة USB، جرافيك ↔ جرافيكس/تصميم. قاعدة بسيطة `if_near_any` ضمن ±5 كلمات → `skip`. لا نحتاج ML.
4. **الترتيب**: الأنماط الأطول أولاً (منع "فلاش" من أكل "فلاش لايت").
5. `hits` يزداد عند كل استبدال → `/glossary` يعرض الأكثر استخداماً أولاً، ويكشف المدخلات الميتة.
6. **قبل الحفظ وقبل الإرسال** معاً (المالك: الأرشيف يجب أن يكون مصححاً أيضاً).

## 4. الأوامر والواجهة [ج6 + ج1 — بعد الدمج]

| الأمر | الوظيفة |
|---|---|
| `/glossary` | قائمة مرقّمة 5/صفحة (`PANEL_PAGE_SIZE`) مع أزرار ⬅️➡️ وزر 🗑️ لكل مدخل (تأكيد مزدوج) |
| `/add_word شلبي = ChatGPT` | إضافة سريعة (`kind=alias`, `scope=polished_only` افتراضياً) |
| `/add_word` بلا وسائط | معالج خطوات (FSM): اللفظ → المقصود → النوع (زرّان) → حفظ |
| `/del_word <id أو لفظ>` | حذف مع تأكيد |
| `/glossary_export` | يرسل `glossary.json` كملف |
| الرد على رسالة تفريغ بـ `صحح: X = Y` | اقتراح إضافة مباشرة من السياق (أخفّ من الأمر) — **P2** |

- **اقتراحات تلقائية** [ج1]: لو ظهرت كلمة غير قاموسية مكررة ≥3 مرات في أسبوع في نصوص خام → "لاحظت تكرار «X» — تضيفها؟" (**P2**، يحتاج عدّاد كلمات بسيط؛ لا ML).
- **إعادة تحميل حية**: القاموس يُقرأ من الذاكرة ويُحدَّث عند كل تعديل — لا إعادة تشغيل (الحجم صغير).

## 5. التفاعل مع المحاور الأخرى

- **البرومبت (06):** إضافة إلى برومبت التفريغ سطر: "المصطلحات التالية قد تُنطق بالعامية: … اكتبها كما نُطقت" — **لا** نطلب من الموديل التصحيح (غير موثوق)، نصحّح نحن بعد النص. الاستثناء: الأسماء التقنية الإنجليزية الواضحة (Antigravity) يمكن تمريرها كتلميح إملائي للموديل.
- **الأرشفة (08):** المدخلات الجديدة لا تُطبَّق بأثر رجعي على الأرشيف تلقائياً؛ أمر `/glossary_reapply <session>` اختياري (P3).
- **الأمان (13):** `glossary.json` لا يحوي أسراراً → يدخل في `/backup` العادي.

## 6. معايير القبول (DoD)
1. اختبارات وحدة لـ `apply_glossary` تغطي: السوابق (و/ب/ال)، التطبيع، `context_rules` (أوبس قرب "ستوديو" لا يتغير)، الأطول أولاً، scope.
2. النص الخام **لا يتغير** عند `scope=polished_only`.
3. الحذف يتطلب تأكيداً؛ `callback_data` ≤ 64 بايت.
4. ملف تالف → يُحمَّل الافتراضي ويُبلَّغ المالك، لا انهيار.
