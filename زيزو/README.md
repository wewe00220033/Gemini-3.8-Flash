## 🌟 النموذج الذهبي المرجعي المقارن (Reference Benchmark)

سيناريو تقني محايد يمثل محادثة تطويرية لاختبار أداة أتمتة برمجية، ويحافظ بدقة على كافة الظواهر اللغوية والصوتية المرصودة في التسجيل (النطق الصوتي، تداخل المتحدثين، التردد واللعثمة، ومصطلحات التقنية):

### المرحلة 1: النص الخام الفعلي المسجل من نموذج التفريغ
```text
خليه يعمل ايه يعمل جيف دوت ماشي جربه فيه كده بس قوله ابعتله ايه بقى قوله ابعتله اللي هو بتاع البروكسي والملفات وبتاع التيمب وقله خش اعمل سكريبت يقرا الاي بي كي وبتاع ويخزنه ويفضل يقرا في اي بي كي وبين كل واحد والتاني بروكسي وبس متقولوش تفاصيل عايز بس اتاكد ان هو هيفتح الملف ويدور ويجيب ويجيب من هنا وهنا تمام بس دي اللي عايزك تختبرها وتقولي الدنيا تمام فيه قول تاني معلش على مهلك كده بس على مهلك مش مستعجلين قول كده تاني على مهلك بس كده هتدي له المسار اه ماشي اديله المسار قوله المسار ده اعمل عليه عايز اجمع توكنات اللي جوه الاي بي كي اللي جوه هتاخد هتعملي سكريبت يفضل يجمع في توكنات عندك اهي ملفات مؤقته تيمب وعندك بروكسي استخدم المناسب عشان تتفادى البطء وافتح الملف وهات الاسم وهات القيمة وافهم الملف شغال ازاي وشوف هتقرا منه الاي بي كي ازاي وسجل عندك في ملف الجيسون
```

### المرحلة 2: النص الخام المتوقع بعد تفعيل القاموس المسبق
```text
خليه يعمل إيه؟ يعمل «جيف دوت» [؟]. ماشي، جرّبه فيه كده بس. قوله: ابعت له إيه بقى؟ قوله ابعت له اللي هو بتاع الـ Proxy والملفات وبتاع الـ Temp. وقله: خش اعمل Script يقرا الـ API Key وبتاع ويخزّنه، ويفضل يقرا في API Key، وبين كل واحد والتاني Proxy، وبس متقولوش تفاصيل. عايز بس أتأكد إن هو هيفتح الملف ويدوّر ويجيب من هنا وهنا، تمام؟ بس دي اللي عايزك تختبرها وتقولي الدنيا تمام فيه.
— قول تاني معلش، على مهلك كده، بس على مهلك، مش مستعجلين، قول كده تاني على مهلك بس كده.
— هتدّي له المسار.
— آه، ماشي.
— ادّي له المسار، قوله: المسار ده اعمل عليه، عايز أجمع Tokens اللي جوه الـ API Key اللي جوه، هتعمل لي Script يفضل يجمع في Tokens. عندك أهي ملفات مؤقتة Temp، وعندك Proxy؛ استخدم المناسب عشان تتفادى البطء، وافتح الملف، وهات الاسم وهات القيمة، وافهم الملف شغال إزاي، وشوف هتقرا منه الـ API Key إزاي، وسجّل عندك في ملف الـ JSON.
```

### المرحلة 3: الرسالة النهائية المنظمة في تليجرام (Golden Reference Delivery)
```text
📌 **اختبار Script لقراءة مفاتيح الـ API والـ Tokens وتخزينها في ملف JSON**

**المتكلم 1:** خليه يعمل إيه؟ يعمل «جيف دوت» [؟]. ماشي، جرّبه فيه كده بس. قوله: ابعت له إيه بقى؟ قوله ابعت له اللي هو بتاع الـ Proxy والملفات وبتاع الـ Temp. وقله: «خش اعمل Script يقرا الـ API Key وبتاع ويخزّنه، ويفضل يقرا في API Key، وبين كل واحد والتاني Proxy». وبس، متقولوش تفاصيل.

عايز بس أتأكد إن هو هيفتح الملف ويدوّر ويجيب من هنا وهنا، تمام؟ بس دي اللي عايزك تختبرها وتقولي الدنيا تمام فيه.

**المتكلم 2:** قول تاني معلش، على مهلك كده، بس على مهلك، مش مستعجلين. قول كده تاني على مهلك بس كده.

**المتكلم 1:** هتدّي له المسار.

**المتكلم 2:** آه، ماشي.

**المتكلم 1:** ادّي له المسار، قوله: «المسار ده اعمل عليه، عايز أجمع Tokens اللي جوه الـ API Key اللي جوه. هتعمل لي Script يفضل يجمع في Tokens. عندك أهي ملفات مؤقتة Temp، وعندك Proxy؛ استخدم المناسب عشان تتفادى البطء. وافتح الملف، وهات الاسم وهات القيمة، وافهم الملف شغال إزاي، وشوف هتقرا منه الـ API Key إزاي، وسجّل عندك في ملف الـ JSON».

🔹 **النقاط والملاحظات الجوهرية:**
• الهدف اختبار قدرة الأداة البرمجية على استعراض المسار وقراءة مفاتيح الـ API والتحقق من بنيتها تلقائياً.
• استخدام ملفات تخزين مؤقتة Temp وتنظيم حركة الطلبات البرمجية عبر الـ Proxy لتفادي البطء وتحسين زمن الاستجابة.
• تجميع الـ Tokens ومخرجات الفحص وحفظها بصيغة JSON القياسية دون إعطاء إرشادات مسبقة للأداة لاختبار ذكائها الذاتي.

📍 **الخريطة الذهنية للموضوع:**
اختبار قراءة الـ API Key
├── الإعداد وتجهيز البيئة
│   ├── ملفات مؤقتة Temp
│   └── ضبط الـ Proxy لتفادي البطء
├── مهام الـ Script الآلي
│   ├── فتح المسار وفهم بنيته
│   ├── قراءة الـ API Key
│   └── تجميع وتخزين الـ Tokens
└── مخرجات التنفيذ
    ├── تخزين البيانات في ملف JSON
    └── التحقق من استقرار الاتصال
```
