# 🏛️ التقرير المعماري والأمني الشامل

## 1️⃣ السياق والأهداف الهندسية (Context & Objectives)

طلب المالك دراسة إمكانية ربط بوت التليجرام بمزود خارجي محلي (Custom Local Provider / Script) لتنفيذ مرحلة تنظيم وتنسيق النصوص (Layer B Polish) كبديل أو مكمل لنموذج `gemini-3.5-flash-lite`، مع الالتزام الصارم بالشروط التالية:
1. **السيادة التامة والأمان المطلق (Zero-Leakage):** السكربت الخارجي يحتوي على أسرار حساسة (Cookies، Sessions، Auth Tokens، Passwords)، ولذلك يجب أن يبقى محلياً بنسبة 100% ويُحظر تماماً رفعه إلى مستودع GitHub أو تضمينه في أي حزم نشر عامة.
2. **الواجهة العامة غير المقيدة (Generic Black-Box Interface):** يتعامل البوت مع المزود الخارجي عبر واجهة قياسية موحدة كـ "صندوق أسود" دون الحاجة لمعرفة آليات اتصاله بالمزود الخارجي أو طبيعة التوكنات داخله.
3. **مرونة التبديل وتجاوز الأعطال (Interchangeability & Automatic Failover):** القدرة على الاختيار بين المزود المحلي ومزود Google AI Studio، مع تفعيل التحويل التلقائي عند حدوث أي خطأ أو تأخير في المزود الأساسي.
4. **حماية طبقة التفريغ الصوتي (Layer A Transcription Core):** عزل تام لنواة معالجة الصوت بالذكاء الاصطناعي، واستحالة تأثر التفريغ الصوتي الخام حتى لو انهار المزود الخارجي بالكامل.

## 2️⃣ التحليل المعماري لواقع الكود الحالي (Ground Truth بالسطور)

بفحص الكود الفعلي المعتمد في المنظومة، تبين أن النظام مبني بالفعل على فلسفة **فصل المسؤوليات المعماري (Decoupled Architecture)**:

```
┌─────────────────────────────────────────────────────────────┐
│              Layer A: التفريغ الصوتي (transcriber.py)        │
│  Gemini 3.0 Pro / 2.5 Flash / 2.0 Flash (حصص ومفاتيح متعددة)│
└──────────────────────────────┬──────────────────────────────┘
                               │ (نص خام فقط)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 Layer B: المساعد النصي (text_assist.py)      │
│  - polish(): إعداد نصوص النظام (Prompts) + الأدوار + القاموس│
│  - generate(): استدعاء النموذج النصي gemini-3.5-flash-lite  │
└──────────────────────────────┬──────────────────────────────┘
                               │ (نص منظم)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                  طبقة التسليم (delivery.py)                 │
│  - تسليم الرسالتين (خام + منظم)                             │
│  - حارس الاستقرار: خطأ التنظيم لا يعطل تسليم الخام أبداً    │
└─────────────────────────────────────────────────────────────┘
```

### الأدلة البرمجية من واقع الملفات:
1. **طبقة التفريغ الصوتي محصنة بحارس صريح:**  
   في `text_assist.py` (سطر 42-49):
   ```python
   def assert_not_transcription_model():
       if model_name() in Config.MODELS:
           raise RuntimeError(f"TEXT_ASSIST_MODEL={model_name()} موجود في Config.MODELS — Lite ممنوع للتفريغ")
   ```
   هذا الحارس يمنع بشكل قاطع أي تداخل بين نماذج الصوت ونماذج النصوص.
2. **طبقة التسليم مهيأة للحقن البرمجي (Dependency Injection):**  
   في `delivery.py` (سطر 201-213):
   ```python
   if polish_fn is None:
       import text_assist
       polish_fn = text_assist.polish
   ...
   except Exception as e:  # دفاع: التنظيم لا يكسر الخام أبداً
       polished, reason = None, f"{type(e).__name__}: {e}"
   ```
   السطر 211 يثبت أن دالة التنظيم قابلة للاستبدال كلياً وأن فشلها معزول دفاعياً.
3. **نقطة الامتداد الجراحية الدقيقة:**  
   دالة `text_assist.generate(system_text, user_text)` هي النقطة الوحيدة التي تتصل بخوادم Google؛ وبالتالي، استبدال هذه الدالة بـ **ProviderRouter** يحقق المطلوب بالكامل دون المساس بـ `delivery.py` أو `telegram_bot.py`.

## 3️⃣ المقارنة المعمارية بين أنماط التنفيذ المتاحة

| وجه المقارنة | النمط الأول: Subprocess CLI Hook (الموصى به) | النمط الثاني: Dynamic Drop-in Module | النمط الثالث: Local HTTP Sidecar |
| :--- | :--- | :--- | :--- |
| **طبيعة الاتصال** | تشغيل سكربت عبر `stdin/stdout` | استيراد مباشر `import provider_local` | استدعاء HTTP عبر `127.0.0.1:port` |
| **مستوى عزل الأسرار** | أقصى عزل (الملف يمكن وضعه خارج المشروع بالكامل) | عالي (ملف محلي داخل المجلد محمي بـ `.gitignore`) | عالي (خادم محلي يستمع داخلياً) |
| **سطح الهجوم الأمني** | شبه منعدم (لا يفتح أي منفذ شبكي) | منعدم (تنفيذ داخلي) | متوسط (يفتح منفذ شبكة محلي TCP) |
| **مرونة لغة السكربت** | أي لغة (Python, Node.js, Go, Bash, C#) | Python فقط ومقيد ببيئة المشروع الافتراضية | أي لغة تدعم إنشاء خادم ويب |
| **إدارة دورة الحياة (SRE)** | استدعاء عند الحاجة + مهلة صارمة + إنهاء العملية | معقدة عند حدوث تجمد في المكتبات الخارجية | تتطلب إدارة خدمة مستمرة في الخلفية (Daemon) |
| **الحكم الهندسي** | **الأفضل والأكثر أماناً وعزلاً** | ممتاز للسرعة لو السكربت كود بايثون نقي | ممتاز فقط لو تهيئة الجلسة تأخذ وقتاً طويلاً جداً |

## 4️⃣ التفتيش الأمني الشامل (Security Inspector 360°)

```
               ┌──────────────────────────────────────────────┐
               │              البيئة المحلية للمطور          │
               │                                              │
               │  مسار خارجي: D:/private/polish_provider.py    │
               │  يحوي: Cookies, Sessions, Passwords, Tokens  │
               └──────────────────────┬───────────────────────┘
                                      │ استدعاء سطر أوامر معزول
                                      │ (stdin/stdout بترميز UTF-8)
                                      ▼
┌─────────────────────────────────────────────────────────────┐
│              مستودع المشروع العام (Git Repository)           │
│                                                             │
│  - config.py: يقرأ المسار من .env المحلي فقط               │
│  - .gitignore: يستبعد .env و keys.json وجميع السجلات        │
│  - tools/pack_deploy.py: يمنع حزم أي مسارات أو ملفات سرية    │
│  - لا توجد أي بيانات اعتماد أو أسماء مزودات في الكود المرفوع│
└─────────────────────────────────────────────────────────────┘
```

### خطوط الدفاع الثلاثة ضد التسريب:
1. **خط الدفاع الأول (المسار السيادي الخارجي):**  
   حفظ سكربت المزود الخارجي في مسار خارجي تماماً عن شجرة ملفات المستودع (مثلاً `D:/private/` أو `~/secure-keys/`). هذا يلغي فيزيائياً أي إمكانية لضم الملف في Git.
2. **خط الدفاع الثاني (تأمين المتغيرات .env):**  
   يتم تمرير أمر التشغيل عبر المتغير `LOCAL_PROVIDER_CMD` داخل ملف `.env` المحلي، وملف `.env` محمي سلفاً في السطر 4 من `.gitignore`.
3. **خط الدفاع الثالث (حارس حزمة النشر pack_deploy.py):**  
   تعتمد أداة الحزم على قائمة سماح صريحة (Explicit Allowlist)، وتقوم بفحص كل عضو ومطابقته بدالة `is_forbidden(rel)` لمنع تسريب أي ملفات خاصة قبل بناء الأرشيف.

## 5️⃣ هندسة استقرار النظم والتحمل (SRE & Resilience)

1. **ميزانية المهلة الزمنية الصارمة (Strict Timeout Budget):**  
   تحديد مهلة المزود المحلي بـ **15 ثانية كحد أقصى**. لا يجوز أبداً ترك البوت معلقاً لفترات طويلة؛ وفي حال انقضاء المهلة يتم قطع الاتصال وتحويل الطلب فوراً إلى المزود السحابي البديل.
2. **حارس العمليات الشبحية (Zombie Killer):**  
   عند حدوث Timeout للعملية الفرعية، يجب إرسال إشارة `kill()` صريحة للعملية لضمان عدم بقائها معلقة في ذاكرة ويندوز واستهلاكها لموارد المعالج والذاكرة.
3. **استراتيجية التبديل المتدرج (Graceful Fallback Chain):**  
   - المحاولة الأولى: المزود المحلي المخصص (Local Custom Provider).
   - المحاولة الثانية (تلقائية عند الفشل): `gemini-3.5-flash-lite` عبر Google AI Studio.
   - المحاولة الثالثة (عند تعذر الاثنين): تسليم النص الخام فوراً للمستخدم مع إشعار توضيحي لطيف دون فقدان الرسالة الصوتية.
4. **حماية نصوص اللغة العربية والرموز التعبيرية على ويندوز:**  
   فرض الترميز القياسي `encoding="utf-8", errors="replace"` في مدخلات ومخرجات موجه الأوامر لمنع انهيار النظام بأخطاء `UnicodeDecodeError` الناتجة عن الترميز الافتراضي للويندوز (`cp1256`).

## 6️⃣ المواصفات البرمجية المقترحة للمتغيرات (Configuration Spec)

تضاف المتغيرات التالية لملف `config.py` مع قراءتها تلقائياً من `.env`:

```ini
# --- إعدادات مزود التنظيم النصي (Pluggable Polish Provider) ---
# الخيارات: 'gemini' (الافتراضي) | 'local' (المحلي فقط) | 'auto' (المحلي أولاً مع تحويل تلقائي لـ Gemini)
POLISH_PROVIDER=auto

# أمر استدعاء السكربت الخارجي (مسار مطلق خارج الريبو تماماً)
LOCAL_PROVIDER_CMD=python D:/private/polish_provider.py

# المهلة القصوى للمزود المحلي بالثواني (ممنوع تجاوز 15 ثانية لضمان استجابة البوت)
LOCAL_PROVIDER_TIMEOUT=15

# تفعيل التحويل التلقائي عند فشل المزود الأساسي (1 = مفعل، 0 = معطل)
POLISH_FAILOVER=1
```
